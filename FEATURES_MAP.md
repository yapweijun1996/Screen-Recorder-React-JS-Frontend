## Navigation

[App.tsx](src/App.tsx#L25) opens the recording surface by default and accepts `?page=converter` on initial load. Use the **ScreenClip Pro** and **WebM Converter** tabs in the header to switch surfaces. The **ScreenClip Pro** tab shows **Edit & Export** when a finished recording is loaded. The converter tab is disabled during capture setup, recording, pause, and capture finalization. Local files selected in the converter go through the conversion workflow. The editor opens a newly completed recording or the saved original. [Navigation controls](src/App.tsx#L63) · [Editor and converter branches](src/App.tsx#L139)

- The release record documents focused Chromium checks for synthetic capture, PIP audio, cancellation and capture failure, timeline commands and gestures, preference storage, and MP4 and WebM downloads. Use source evidence for other rows. The current smoke matrix adds Chromium and Firefox synthetic capture, draft recovery and downloaded tracks, plus the unsupported conversion response in bundled Windows WebKit. Physical capture, background PIP and Safari remain pending. [Browser matrix](docs/BROWSER_VERIFICATION.md) [Release verification](task.md) · [Bug register](bug.md)
- Chromium checks with disposable fixtures covered legacy identity recovery, cross-tab reset protection, native keyboard file browsing, clip trimming, timeline seeking and cancelling an export with Escape. [Improvement evidence](improvement.md)
- **Maintenance.** Keep feature IDs stable when labels or navigation change. Refresh affected source links and record the new source revision. Record a browser result only after observing the expected result and a negative case on the matching build.
